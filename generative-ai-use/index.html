Generative AI Use

It’s a matter of fact that generative AI (AI hereafter) is here to stay in some way shape, shape, or form. It would be naive to think that in 10 years time we won’t be using AI to help write code just like how we use autocorrect to help us spell and Wordpress to help build websites.

Coding is laborious, and fun! But it does take time and it can really slow down projects which deserve to exist but can’t due to development costs. AI helps ease some of those difficulties and ultimately supports us developers in getting things done!

How OpenBat uses generative AI

I’m a solo developer with a full time job, hobbies & interests, responsibilities, a charity to help run, voluntary projects to manage…there is a lot going on. AI helps me build and maintain OpenBat so that it can inspire people to care more about bats, and do all the other things life throws my way.

I follow a set of rule, or principles, which guide my use of AI. Yes, I let AI write code. It’s fast and fairly efficient (on cost for sure!).

Rules:

  1. I never let AI make decisions for me: each design choice, layout, colour, word, and icon is selected by me. I spent hours fiddling with colours in Affinity, browsing SF Symbols, and drafting wording in Obsidian. I decide what goes where.
  2. I read everything AI writes: every line of code is read by me. Admittedly there are the odd lines which are unfamiliar to me, but I google, stack-overflow, search…and I learn.
  3. I test, test, and test again: whenever I use AI to write code, I test it to the limit. My partner will attest the the countless hours I’ve spent wandering the streets testing new code on real bats. But before I even get outside, I run unit-tests on all of my builds.
  4. I don’t use AI for code I can write efficiently: I write the code that doesn’t slow me down. Configuring a view, lining up a sheet, tweaking some .OnChange behaviour. I am meticulous about the code I write, and i know when I’m slowing me down. AI is great at documenting what code does, I make use of this often so future me (or someone else) knows what is going on!
  5. I look for bugs…most of the time: I check for bugs and follow them home myself. But sometimes, it’s just tedious work. AI is great at spotting these complex bug flows and is great at generalising to other areas of the codebase. I work to my strengths and delegate when I need to.
  6. Every day is a school day: learning is my main priority. If I want to design something I go and research it. I learned so much about DSP (digital signal processing) during the main dev stretch on this app, it was amazing! Phase Vocoder anyone?
